# Handoff prompt

Copy everything in the block below into a fresh agent session opened in this repo folder.

```
You are taking over the FairShed build mid-run. FairShed is a fair, auditable load-shedding
planner for a Qiskit hackathon (Energy & Smart Infrastructure). The previous session ran out
of usage limit. Do not restart; continue from where it stopped.

1. Read, in this order: docs/PROGRESS.md (what is done / partial / not started, plus
   decisions already made), docs/SPEC.md (the full original brief: it is your acceptance
   criteria, including the HONESTY RULES and the build order M1-M9), docs/CONTRACT.md (the
   data contract between the three areas), docs/KNOWN_ISSUES.md.
2. Run `git status` and `git log --oneline | head -20` to see what was committed last, and
   `git pull --rebase origin main` if the remote has moved.
3. Verify the real state before trusting PROGRESS.md (subagents were mid-flight when it was
   written):
     .venv/Scripts/python.exe -m pytest -q
     .venv/Scripts/python.exe scripts/validate_results.py
   If .venv is missing: `py -3.11 -m venv .venv` then
   `.venv/Scripts/python.exe -m pip install -r requirements.txt`.
4. Continue with the "Next steps, in order" list at the bottom of docs/PROGRESS.md, then the
   remaining milestones of docs/SPEC.md (M1-M9). Finish every item: Makefile + scripts/tasks.py,
   quantum stages (ablation, lottery, pareto, counting, risk, GAS, MPS scaling), replay with
   the quantum window solver, the seven dashboard screens with a smoke test, the report with
   tables generated by scripts/fill_report.py, README, docs/demo_script.md, docs/AREAS.md.
5. Rules that still apply:
   - Honesty: never fabricate a number; every figure comes from running the code. If a part
     cannot be made to work, mark it NOT WORKING in docs/KNOWN_ISSUES.md, make the UI show
     "not available", and move on. Simulator only, no speed-up claims, synthetic data is
     labelled synthetic.
   - Verify every Qiskit API against the installed, pinned versions (qiskit 2.6.2,
     qiskit-aer 0.18.2, qiskit-algorithms 0.4.0, qiskit-optimization 0.7.0).
   - Keep the three areas separate (Area 1 src/quantum; Area 2 src/data, src/cost,
     src/classical, src/export, src/audit, src/replan, src/forecast; Area 3 ui/). They talk
     only through results/*.json and schemas/. Area 1 never imports Area 2 code.
   - Bit order: results `bits` are index-ordered (bits[t*N+f]); Qiskit count keys are the
     reverse. Tests guard this; keep them passing.
   - Commit and push to origin main at the end of every milestone with a clear message, and
     update docs/PROGRESS.md in the same commit so the next session can resume.
   - Do not stop to ask questions between milestones. Give a completion-time estimate every
     20 minutes or so.
6. When everything is done: run the test suite and the full demo from a clean virtual
   environment, fix failures, then print what works, what does not, and the exact commands
   to run.
```
